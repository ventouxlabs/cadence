# Decisions log

Every default chosen without asking JD. Newest at the bottom of each section. Format: **D-NNN** · date · decision · why · how to change.

## Phase 0 — Discovery (2026-09-06)

- **D-001** · Repo lives at `github.com/ventouxlabs/cadence` (public), not under `bearyjd`. Why: the brief brands the project "Ventouxlabs" and JD asked for a public GitHub repo mid-build; the `ventouxlabs` org exists and is writable. Change: `gh repo transfer`.
- **D-002** · `main` is pushed after every PRP squash-merge and tag. Why: JD asked for the public repo, so keeping it current is the point; nothing secret is ever committed (`.env` is git-ignored). Change: drop the `git push` from the merge step.
- **D-003** · Codex adversarial review runs as `codex exec --model gpt-5.1-codex "<brief>"` (the brief said `codex -q`, which this Codex CLI 0.151 no longer accepts). If the model is unavailable, fall back to a second independent reviewer subagent and log it per PRP.
- **D-004** · Container runtime is `podman` + `podman-compose` (this workstation aliases `docker` → `podman`). Compose files stay Docker-compatible; VM-201 runs Docker Compose. Change: none needed.
- **D-005** · VitalForge is read from the existing clone at `../vitalforge` (already present, `origin` = bearyjd/vitalforge). The PRP-05 branch is created there and never pushed.
- **D-006** · Python is pinned to 3.12 via `uv` (`.python-version`), even though the host default is 3.14. Why: the brief says 3.12; VitalForge and its `garminconnect==0.3.11` pin are known-good on 3.12.
- **D-007** · Superpowers "brainstorming" skill is skipped for this build. Why: JD explicitly forbade questions and approval gates; the brief plus `docs/exercise-principles.md` stand in for the brainstorm. Open questions become settings or entries here.
- **D-008** · "French naming convention" is applied as: French names for the project, services, containers, and top-level domain modules (`bibliotheque`, `programme`, `seance`, `profils`, `historique`, `bilan`, `validateur`, `ia`); English for classes, fields, JSON keys, and routes so the API lines up with VitalForge and Garmin. See `docs/architecture.md` §2.
- **D-009** · Cadence has no login of its own. It is reachable only over Tailscale (and optionally an NPM access list). Why: a login screen makes Today slower for a kid; the brief's security boundary is the homelab. Change: add a middleware reading `CADENCE_ACCESS_TOKEN` (PRP-09 documents how).
- **D-010** · Imported and AI-generated workouts live in the DB only (`source = import|generated`); the app never writes to `library/`. Why: removes path-traversal surface from `/api/import`; seed YAML stays reviewable in git.
- **D-011** · The 4-week plan is a rolling ordered list, not calendar-bound. "Today" = the next unfinished planned session for the profile. Why: missed days must not pile up as guilt; the brief says a missed session holds progression.
- **D-012** · HTMX (and nothing else) is vendored into `cadence/web/static/`; no CDN, no build step. Why: offline PWA on a low-end Android phone; page-weight budget.
- **D-013** · Together mode is two sessions linked by `together_group_id`, one Done. Why: write-back must stay per person and per Garmin-push setting.
- **D-014** · Codex CLI on this machine is signed in with a ChatGPT account, which rejects `gpt-5.1-codex` ("not supported when using Codex with a ChatGPT account"). Adversarial reviews use the CLI default model `gpt-5.6-terra` (probe returned OK); if that fails on a given PRP, a second independent Claude reviewer subagent runs the same brief and the PRP log says so.
- **D-015** · VitalForge holds one Garmin credential (the parent's). `POST /p/{slug}/api/activity` with `push_to_garmin: true` for a different person returns 409 **unless** the body also carries `garmin_target: "credential_person"`, in which case the activity is created under the parent's Garmin with the name prefixed by the person's display name (e.g. "Cadence (Son) — Lower A"). Cadence sends that field only when the `push_son_to_garmin` setting is on. Why: the brief wants opt-in pushing of the son's sessions to JD's account; the contract wants no silent misfiling. Both hold.
- **D-016** · Cadence's write-back retry is a bounded, client-driven re-POST of the same `session_id` (exponential backoff 1 min → 2 h, max 8 attempts, never on 409/422). Why: VitalForge has no retry worker and `garminconnect` has no 429 backoff; a tight loop could get the shared credential blocked and break weight logging too (contract §5.9).
- **D-017** · Person slugs default to `me` → `VITALFORGE_PERSON_ME` and `son` → `VITALFORGE_PERSON_SON` env vars (blank in `.env.example`); editable in Settings. Why: VitalForge persons are path slugs and Cadence cannot list them without admin.
- **D-018** · `UNKNOWN` is not a `garminconnect` 0.3.11 exercise category (contract §3.1). In the schema `garmin_category` is `Optional[str]` validated against the 26 confirmed names; wherever `docs/exercise-principles.md` says `UNKNOWN`, the seed YAML uses `null`, the activity payload omits the field, and VitalForge skips exercise-set upload for that exercise (the activity itself is still created).
- **D-019** · Adopted the principles doc's judgment calls verbatim: `load_unit` enum (`per_hand`/`per_implement`/`total`/`bodyweight`); kettlebells illegal under 14, two-handed 16 kg max for 14–17 with a 45.7 kg bodyweight gate, 24 kg adult-only; youth loaded rep floor 8; `has_overhead_anchor` profile boolean (dead hang records `unavailable`, never a gap, without it); `bench_assisted` legal under 10; illegal loads clamp down instead of rejecting a row at program-build time (the *validator* still rejects imported/generated docs that break caps); Done always tappable with a per-band promotion threshold; precedence rules P1–P7.

## Phase 1 — PRPs (2026-09-06)

- **D-020** · PRP-05's VitalForge branch `cadence/activity-endpoint` is cut from the clone's checked-out `fix/a6-review-followups` (2 commits ahead of `main`), because that is the tree the contract's citations and the `should_attempt_garmin_push` helper live in. JD rebases when merging.
- **D-021** · Son's `push_to_garmin` is exactly the `push_son_to_garmin` setting (architecture §5), not an AND with a per-profile flag. PRP-06 reads the setting at payload-build time.
- **D-022** · `ActivityIn` gains `garmin_target` and `session_label` (needed for D-015 under `extra="forbid"`) and per-exercise `seconds` (planks/carries cannot be expressed as `reps`). `muscle_mass` from VitalForge metrics is grams and is divided by 1000 like `weight`.
- **D-023** · Table ownership follows build order, not subject: PRP-01 owns `profile`/`setting` tables and `age_band()` (seed needs demo profiles); PRP-02 owns `session`/`session_row`; PRP-03 owns the services and screens over profiles/settings; PRP-04 owns history queries, scorecard, streak.
- **D-024** · The session row is created on first render of Today (not first tick, as architecture §3 first said) so the offline queue has a `session_id` before the first tap; `started_at` is still set on the first tick.
- **D-025** · Page-weight budgets are gzip transfer bytes (HTML < 30 KB, JS < 25 KB, CSS < 10 KB, 60 KB hard gate for `/today`); `GZipMiddleware` is the one middleware allowed in `create_app()`.
- **D-026** · Generate goals map onto the principles §11 `GoalType` enum with plain-language UI labels; the brief's `play`/`coordination` are labels, not new enum values.
- **D-027** · Youth banned-word check: banned phrases over the full DOM text, bare words (`weight`, `fat`, `lean`, `abs`) scoped to metric and challenge-name elements only, with a non-vacuity assertion, because "refuse to lean" is a legal cue. Assessment day gets the posture prelude prepended.
